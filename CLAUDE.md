# CLAUDE.md

Guidance for working in this repository.

## Project

PugliAI — a bilingual (Italian/English) **static** marketing site for an Italian AI consulting firm targeting SMBs (PMI). Plain HTML/CSS/JS with **no frameworks and no runtime dependencies**: the committed HTML files are served exactly as they are by GitHub Pages. The site's job is lead generation: contact-form submissions, free strategy sessions, accelerator applications.

See `PRODUCT.md` for brand register and positioning.

## How the pages are produced

Since the September 2026 redesign the HTML is generated by a small Python generator (Python 3.11, standard library only) in `tools/site-generator/`. **The generator is the source of truth for every page except the blog articles.** Edit the module, run the build, commit the module *and* the generated HTML together.

```bash
python3 tools/site-generator/build.py              # regenerate every page (IT, EN, articles)
python3 tools/site-generator/build.py pages_home   # one module
python3 tools/site-generator/sitemap.py            # regenerate sitemap.xml from the page list
```

- `gen/site.py` — `Page` dataclass, `<head>` (canonical, hreflang, OG/Twitter, GA4 with Consent Mode defaults, JSON-LD), page shell, footer, organisation data (`ORG`), `UPDATED_*` dates.
- `gen/html.py` — component helpers (buttons, cards, tabs, tables, forms, page heads, stats, steps, FAQ…).
- `gen/templates.py` — `detail_page()` and the section kinds most pages are built from.
- `gen/pages_*.py` — page content, IT and EN side by side in the same module (home, services, products, sectors, about, contact, accelerator, resources, ROI calculator, legal).
- `gen/data_articles.py` — the article index used by the resources hub and the CEO guide.
- `gen/articles.py` — re-wraps the 39 blog articles in `guida-ai/` in the current shell. Their copy lives only in the HTML (inside `<article>`), so edit the article file directly, then re-run the build: the module is idempotent and only refreshes head, chrome and scripts.

If you must hand-edit a generated page, port the change into the generator first, otherwise the next build overwrites it. The old navy/gold pages and the 2026 "olive-tree" dark theme exist only in git history — never resurrect them.

## Run locally & verify

```bash
python -m http.server 8000   # http://localhost:8000/index.html   (English: /en/index.html)
```

- `.claude/launch.json` defines preview servers: `pugliai` (port 8765) and `pugliai-8788` (fallback when 8765 is taken).
- Screenshots: use the repo's `playwright-core` (already in `node_modules`). On a developer machine the bundled Chromium is **not** installed, so launch with `chromium.launch({ headless: true, channel: 'msedge' })`; in a cloud sandbox point `executablePath` at the Chromium under `PLAYWRIGHT_BROWSERS_PATH`. Full-page captures can leave lazy-loaded photos blank — that is a capture artifact, check with a viewport screenshot before "fixing" it.

## Structure

- **Italian pages** live at the repo root (`servizi.html`, `chi-siamo.html`, …). Run `ls *.html` for the current list.
- **English pages** mirror them in `/en/` with English filenames (`servizi.html` → `en/services.html`, `contatti.html` → `en/contact.html`, `risorse.html` → `en/resources.html`, …). The IT↔EN map is `IT_TO_EN` in `src/assets/js/navigation.js` (used by the language toggle); keep it in sync when adding pages.
- **Articles** live in `/guida-ai/` (Italian only, no English mirrors; `alt=None` in the generator).
- **Assets** in `src/assets/`: `css/stylesheet.css` (the only stylesheet), `js/navigation.js` (announce bar, header, dropdown nav and mobile panel, injected into `#nav-placeholder`), `js/consent.js` (cookie banner + preferences dialog, Google Consent Mode v2), `js/form-security.js`, `fonts/` (self-hosted Geist woff2), `img/2026/` (photos, logo mark and wordmark, OG image).
- `src/assets/js/language-switcher.js` is legacy and no longer referenced by any page.
- `src/components/footer.html` is a static copy of the generated IT footer, kept for reference; pages carry their footer inline. `src/components/stylesheet.html` is the pre-2026 design reference and is not part of the site.
- **Funnel landings** (`sessione-strategica.html`, `en/strategy-session.html`) use the minimal header (`own_header=True`) and a sticky CTA; follow the existing page, not the standard template.

## The rule that matters: bilingual parity

Italian is the source of truth. **Every content change must be made on both the root (IT) page and its `/en/` mirror.** In the generator the two languages sit next to each other in the same module — change both.

## Contact data

The only official contact is **sales@pugliai.com**. The company has **no public phone number** — never add one. Fake `+39` numbers and `@pugliai.it` addresses previously shipped in visible copy and JSON-LD and had to be purged; never invent contact data. The office addresses (Latiano BR and Bergamo) and the company identifiers live in `ORG` in `gen/site.py`.

## Claims and numbers

Keep the site's own published figures (package prices, product tiers, the "150% ROI within 12 months or we keep working at no extra cost" guarantee, the 2026 ISO/IEC 42001 milestone) and nothing that cannot be sourced: no invented client results, certifications, percentages or badges. The sector scenarios on `casi-studio.html` are labelled illustrative and must stay that way; the ROI calculator states every assumption it uses.

## Forms & analytics

- Lead forms POST to Formcarry (`https://formcarry.com/s/xWKwXtJvS4C`) with class `contact-form`; `form-security.js` adds validation, a honeypot and a CSRF token.
- Every lead form has `data-ajax="true"` (inline `#form-success` message) and a hidden `source` field naming the page; the shell emits the GA4 `generate_lead` MutationObserver automatically when a `Page` has `form_source` set.
- GA4 (`G-L7711R1PDP`) is on every page, gated by Consent Mode: the head reads the stored `cookieConsent` choice and `consent.js` updates it. Do not add tags that bypass the banner.

## SEO / structured data

Every page carries Schema.org JSON-LD in `<head>` (WebPage/Service/Product/FAQPage/BreadcrumbList as appropriate), plus canonical, hreflang (`it-IT`, `en`, `x-default` = Italian), OG/Twitter meta. Keep JSON-LD in sync with the visible content (never ship FAQ schema without a visible FAQ) and verify it still parses after editing. `sitemap.xml` is generated — run `sitemap.py` after adding pages.

## Design tokens (2026 system)

Defined in `stylesheet.css`; use them rather than hard-coded values:

```css
--color-parchment: #f2f0eb;   /* page background */
--bg-elev: #ffffff;           /* cards, white sections */
--color-ink: #292827;         /* text, dark surfaces */
--text-2 / stone: #666666;    /* secondary text */
--color-wine: #421d24;        /* ONLY primary buttons, announce bar, footer, CTA boxes */
--color-violet: #714cb6;      /* links, eyebrows, tag text (--accent) */
--color-lilac: #d4c7ff;       /* secondary surfaces, tags, selected states */
--color-lagoon: #0c4243;      /* the dark "band" section only */
--radius: 16px;               /* cards and buttons; 8px tabs, 999px pills */
```

Conventions: Geist at weights light/regular/medium (`--w-light`, `--w-regular`, `--w-medium`), tight negative letter-spacing on headlines, **no drop shadows, no gradients** (except the CTA band), no gradient text, BEM-like class names (`.block__element--modifier`), mobile-first, WCAG 2.1 AA. Legacy aliases (`--primary-navy`, `--accent-gold`, …) still resolve to the new palette for the few remaining old classes; do not use them in new code.

## Motion

Animation is a dependency-free port of the Framer Motion model (`initial` /
`whileInView` / variants / staggered children / spring easing) — the library
itself is React-only and cannot ship here. See the `framer-motion` skill in
`.claude/skills/` for the full reference.

- `src/assets/js/motion.js` decides *when* something moves; the
  `/* ---------- Motion system ---------- */` section of `stylesheet.css` owns
  every resting state, easing and transition. Markup only declares intent
  through `data-motion*` attributes, built by `mo()` in `gen/html.py`.
- **Opt-in per page**: `Page(motion=True)` emits the blocking `<head>` snippet
  and the script tag. Currently on the homepage (IT + EN) only. Without it the
  `.motion` class is never added and every `data-motion` attribute is inert.
- Content is never hidden by JavaScript: the class is added only when the
  runtime can work and the visitor has not asked for reduced motion, and a
  failsafe restores the finished state if `motion.js` fails to run. After any
  change, verify the page with motion on, with reduced motion, with JavaScript
  off, at mobile width and in `/en/` — nothing may stay invisible, and the
  settled layout must match the reduced-motion render exactly.
- Keep entrances restrained (620ms, 12–30px of travel, 70–120ms stagger). The
  design system still forbids drop shadows and gradients.
- Do not make any `<script>` in `<body>` parser-blocking: it delays every
  deferred script, and the hero would sit invisible until it resolves.

## Adding a page

1. Add the IT and EN specs to the right `gen/pages_*.py` module (or a new module listed in `MODULES` in `build.py`), with `path`/`alt` pointing at each other, title, description, JSON-LD types and sections.
2. Run the build, then `sitemap.py`.
3. Add the pair to `IT_TO_EN` in `navigation.js` (and to the nav/footer config in `navigation.js` / `gen/site.py` if it belongs there).

## Deployment

Pushing to `main` auto-deploys to GitHub Pages (domain: pugliai.com). No build step runs on deploy — commit the generated HTML. Commit and push only when asked.

## Italian market context

Audience is Italian PMI: EUR (€) pricing, GDPR-relevant, CET/CEST. Italian copy should read as current, professional Italian — avoid gratuitous anglicisms ("sfide", not "challenge"). Specialized agents in `.claude/agents/`: `italian-tech-copywriter` (Italian tech copy) and `ui-ux-designer` (design-system/UX work).
